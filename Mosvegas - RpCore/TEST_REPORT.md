# Mosvegas Core 0.0.4 — отчёт проверки

## Проверка 0.0.4

Проверка выполнена 15 октября 2026 года. Сборка: JDK 21 с `--release 17` (JAR работает на Java 17 и новее), локальный Gradle cache, без интернета.

- `gradlew --offline clean build -Psmoke runSmokeServer` — **BUILD SUCCESSFUL**, создан `build/libs/mosvegas-core-0.0.4.jar`.
- `ZonePolicyTest` — **3019 assertions passed**.
- Серверный Fabric smoke test — **105 assertions passed** (было 66–74). Новые проверки недвижимости на реальных Fabric callbacks:
  - П-образная квартира из трёх частей: все три части закрыты для постороннего (`doors`, `containers`, `interact`, `entities`, `build`), двор между крыльями свободен, PvP не затронут;
  - свободная квартира закрыта; `/property` постороннего не показывает свободные объекты;
  - ПКМ по двери свободной квартиры не открывает дверь и предлагает покупку; покупка списывает цену и назначает владельца;
  - владелец открывает сундук, посторонний — нет (реальный `UseBlockCallback`); чужая несдаваемая квартира у двери не предлагается, сдаваемая — предлагает «Арендовать»;
  - участник получает доступ, после удаления теряет;
  - `/property` владельца показывает только его объект, в карточке нет телепорта, есть продажа;
  - старые `min`/`max` при загрузке конфига переносятся в `areas` и продолжают защищать.

Двухклиентный стенд (`run-multi-test.ps1`, MosvegasOp + MosvegasCitizen) запущен с 0.0.4, подготовлены две П-образные квартиры (`scripts/multi-property-setup.mcfunction`, `TWO_PLAYER_TEST.md`, раздел 8). Сервер и оба клиента подключились без ошибок мода. Ручные действия игроков в этом отчёте не подтверждаются.
## Проверка 0.0.3

Проверка выполнена 30 сентября 2026 года на Fabric 1.20.4 и Java 17 из Minecraft Launcher. Сборка использовала локальный Gradle cache и не требует интернет-доступа.

### Автоматические проверки

- `dev.ps1 -Mode build -Offline` — успешно; создан `build/libs/mosvegas-core-0.0.3.jar`, выполнены compile, remap, unit test и policy test.
- `ZonePolicyTest` — **3019 assertions passed**: границы, измерения, приоритеты, пересечения, ACL игроков/фракций и индекс AABB.
- `dev.ps1 -Mode test -Offline` — серверный Fabric smoke test: **66 assertions passed**.
- `dev.ps1 -Mode test -WithTacz -Offline` — production-style Fabric сервер с собранным TaCZ из `MosVegas - tacz`: **66 assertions passed**.
- Smoke проверяет реальные Fabric callbacks/mixins: команды магазинов и зон, сохранение/reload, NBT и количество товара, баланс, нехватку денег/места, stale revision, открытие меню, shift-click, build, chest, explosion, fire, farmland, falling blocks, PvP, potion, транспортный footprint и callbacks `GunShootEvent`, `GunFireEvent`, `EntityHurtByGunEvent.Pre`.

Логи финального прогона: `build/final-verified-test.log`. Результат smoke: `run-smoke-production/smoke-result.txt`.

### Клиент

Запущен `run-production.ps1 -Mode client -WithTacz`. Открыто окно `Minecraft* 1.20.4 - Singleplayer`; игра создала отдельный мир `run-zone-tests`, загрузила Mosvegas Core и TaCZ, зарегистрировала события стрельбы и отрисовала ресурсы оружейного мода. Процесс оставлен открытым для ручной проверки. Лог запуска: `build/client-test.log`.

Предупреждения о запросе публичного ключа Mojang появляются из-за ограниченного сетевого доступа среды и не относятся к модам. TaCZ также пишет свой `No data fixer registered for target_minecart`; загрузка и тесты завершаются успешно.

### Ручной сценарий

Полный сценарий с командами находится в `SHOPS_ZONES_GUIDE.md`. Короткая последовательность:

1. Администратор создаёт `city` и `police_station`, назначает `build/terrain deny`, `doors/containers members`, `pvp/shoot deny`, выдаёт `police` права на двери и сундуки.
2. Обычный игрок проверяет свободное перемещение, отказ ломать/ставить, двери/сундук и несколько типов стрельбы. Игрок полиции проверяет только разрешённые двери/сундуки.
3. Проверяются TNT, взрывной патрон TaCZ, огонь, ведро, поршень, жидкость, воронка, падающий песок и редстоун двери на границе зоны.
4. В магазине добавляется предмет из руки с NBT, проверяются цена за пачку, покупка с банковского счёта, нехватка денег/места и устаревшее подтверждение.
5. После `/mosvegas reload` и перезапуска мира повторно проверяются JSON-зоны, ACL, цена/NBT магазина и баланс.

Для тестового транспорта используйте API и команды из `transtortintegration.md`; ядро проверяет весь bounding box машины, но вызовы должны быть добавлены в серверный код транспортного мода.

### Дополнительная проверка двух клиентов

При подготовке отдельного сервера найден и исправлен разбор `minecraft:overworld` в команде `zone world`: строковый аргумент без пробелов не принимал двоеточие, теперь используется Minecraft Identifier. Добавлены проверки снятия/возврата защиты Overworld и добавления/удаления внешнего ID измерения.

Повторный `dev.ps1 -Mode test -WithTacz -Offline`: BUILD SUCCESSFUL, 3019 проверок политики и **74 серверные проверки**. Лог: `build/multi-final-test.log`. Обновлённый JAR скопирован в `release` и во все три папки локального стенда.

Стенд: `run-multi-server`, `run-multi-op`, `run-multi-player`; игроки MosvegasOp (OP 4) и MosvegasCitizen (без OP), сервер 127.0.0.1:25565. Сценарий ручной проверки и команды: `TWO_PLAYER_TEST.md`. Площадка и магазин подготовлены серверными командами; это не означает, что все действия двух игроков проверены вручную.

В 16:59 по Москве сервер подтвердил двух игроков онлайн. Проверено командами: MosvegasCitizen — выживание, здоровье 20/20, позиция 6.5/200/12.5, полный тестовый инвентарь; MosvegasOp — творческий режим и единственная запись OP 4. В SQLite у обоих баланс 5000, фракции отсутствуют, дополнительных permission nodes нет. Зона `police_test` и магазин `demo` сохранились после перезапуска.

При одновременном первом входе замечен ConcurrentModificationException в vanilla RegistryOps при отправке реестров (Netty). Раздельное подключение успешно; скрипт запуска теперь ожидает вход первого клиента перед запуском второго. Видеозапись этого запуска не выполнялась.

После сообщения пользователя о невидимых окнах установлено: первый запуск создал GUI на изолированном рабочем столе среды выполнения. Клиенты перезапущены через `javaw.exe` вне sandbox, в обычном пользовательском рабочем столе. Наличие окна администратора и отрисованной площадки дополнительно подтверждено средствами Windows Computer Use; одних логов подключения для проверки видимости недостаточно.
