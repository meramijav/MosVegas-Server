# Mosvegas Core 0.0.4 — руководство по установке и использованию

Новые магазины, серверная защита города, команды зон и подробный сценарий тестирования описаны в [SHOPS_ZONES_GUIDE.md](SHOPS_ZONES_GUIDE.md). Подключение будущего транспорта — в [transtortintegration.md](transtortintegration.md), результаты сборки и проверок — в [TEST_REPORT.md](TEST_REPORT.md). Для установки используйте `mosvegas-core-0.0.4.jar` вместо прежнего JAR.

## Что нового в 0.0.4

Это обновление полностью касается недвижимости:

- **Чужая квартира закрыта полностью.** Раньше посторонний не мог открыть только дверь. Теперь внутри чужого объекта нельзя ничего: открывать сундуки, нажимать кнопки и рычаги, пользоваться верстаком и кроватью, трогать рамки, стойки и мобов, ставить и ломать блоки. Свободная (никем не купленная) квартира тоже закрыта для всех. Подробнее — в разделе [«Кто может пользоваться квартирой»](#кто-может-пользоваться-квартирой).
- **Квартиры любой формы.** Границу объекта теперь можно собрать из нескольких прямоугольных частей: квартира буквой Г, буквой П, в два этажа и т. д. Пошагово — в разделе [«Квартира сложной формы»](#квартира-сложной-формы-г-п-несколько-этажей).
- **`/property` показывает только свои объекты.** Каталог свободной недвижимости и телепорт из меню игрока убраны. Купить или арендовать объект можно, нажав ПКМ по его двери.

Что сделать при обновлении с 0.0.3 — в разделе [«Обновление с 0.0.3»](#обновление-с-003).

## О моде

Я сделал Mosvegas Core как единое RP-ядро для Minecraft 1.20.4 на Fabric. В одном моде я объединил паспорт и лицензии, банковскую систему с физическими купюрами, автоматическую зарплату, фракции, квесты, уровни, недвижимость, парковки и систему прав.

Я реализовал интерфейсы через внутриигровые меню, поэтому игрокам не нужно запоминать большое количество сложных команд. Команда открывает нужное меню, а дальнейшие действия выполняются кнопками.

## Требования

Для работы я использовал:

- Minecraft 1.20.4;
- Fabric Loader 0.16.14 или совместимую версию не ниже 0.15.0;
- Fabric API 0.97.3+1.20.4;
- Java 17 или новее.

Основной файл мода: `mosvegas-core-0.0.4.jar`.

Мод написан на чистой Java без нативных библиотек, поэтому работает на любой системе с Java 17, а JAR весит около 0,2 МБ. До версии 0.0.4 включительно в нём лежал драйвер SQLite с нативными библиотеками для 24 платформ, и JAR весил около 14 МБ.

Файл `mosvegas-core-0.0.4-sources.jar` предназначен только для разработчиков. Его не нужно устанавливать в папку `mods`.

## Установка

Я рекомендую устанавливать один и тот же основной JAR и на Fabric-сервер, и всем игрокам на клиент. Серверная часть отвечает за данные и игровую логику, а клиентская — за корректную работу интерфейсов, контуров недвижимости и маркеров квестов.

1. Я устанавливаю Fabric Loader для Minecraft 1.20.4.
2. Я добавляю совместимый Fabric API в папку `mods` сервера и клиента.
3. Я копирую `mosvegas-core-0.0.4.jar` в папку `mods` сервера и каждого клиента.
4. Я запускаю сервер. При первом запуске мод сам создаёт конфигурацию `config/mosvegas-core.json`.
5. Я проверяю консоль. При успешной загрузке появляется сообщение `Mosvegas Core загружен`.

Перед обновлением я рекомендую остановить сервер и сделать резервную копию:

- `config/mosvegas-core.json`;
- `<папка мира>/mosvegas-core-data.json`;
- на сервере с версией 0.0.4 или старше — все файлы базы: `mosvegas-core.db`, `mosvegas-core.db-wal` и `mosvegas-core.db-shm`. Эти версии держат свежие данные в `-wal` даже после остановки, поэтому одного `.db` мало.

Самый безопасный вариант — копировать данные только после полной остановки сервера.

### Обновление с 0.0.4

Полная методичка для администраторов, с проверкой переноса и восстановлением: [DATA_MIGRATION_GUIDE.md](DATA_MIGRATION_GUIDE.md).

1. Я останавливаю сервер и делаю резервную копию `config/mosvegas-core.json` и всех трёх файлов `mosvegas-core.db*`.
2. Я заменяю JAR на сервере и у всех игроков.
3. Я запускаю сервер. Мод сам переносит базу в `<папка мира>/mosvegas-core-data.json`, а старые файлы переименовывает в `mosvegas-core.db.migrated`, `mosvegas-core.db-wal.migrated` и `mosvegas-core.db-shm.migrated`. В консоли появляется `SQLite-база … перенесена в …`. SQLite для этого не нужен: мод читает файлы базы сам.
4. Если базу прочитать не удалось, сервер останавливается с ошибкой `Нельзя безопасно загрузить данные Mosvegas Core` и ничего не перезаписывает. Тогда я возвращаю прежний JAR: база остаётся нетронутой.

Откат на 0.0.4 после переноса тоже автоматический: 0.0.4 не находит `mosvegas-core.db`, создаёт новую базу и импортирует в неё `mosvegas-core-data.json`.

### Обновление с 0.0.3

1. Я останавливаю сервер и делаю резервную копию `config/mosvegas-core.json` и всех файлов `mosvegas-core.db*`.
2. Я заменяю `mosvegas-core-0.0.3.jar` на `mosvegas-core-0.0.4.jar` на сервере **и у всех игроков**. Старый клиент может показать не все части границы сложной квартиры.
3. Я запускаю сервер. Мод сам переписывает старые границы `min`/`max` в новый формат `areas` и сохраняет конфиг. Вручную ничего править не нужно. Купленные квартиры, владельцы, арендаторы и участники остаются как были.
4. Я предупреждаю игроков:
   - свободные квартиры теперь закрыты: войти в такую квартиру и что-то открыть нельзя, пока её не купят;
   - в `/property` больше нет каталога и телепорта: купить или арендовать объект можно ПКМ по его двери;
   - в чужой квартире нельзя трогать ничего, даже если дверь кто-то оставил открытой.
5. Я проверяю, что у каждой квартиры дверь находится **внутри** границы. Только такая дверь закрыта для посторонних и предлагает покупку. Как это проверить — в разделе [«Проверка готовой квартиры»](#проверка-готовой-квартиры).

## Быстрый старт игрока

Для первого входа я предусмотрел следующий порядок:

1. Я ввожу `/mfc` и оформляю паспорт.
2. Я ввожу `/bankcard` и получаю банковскую карту.
3. Я беру карту в основную или вторую руку и нажимаю ПКМ по банковскому терминалу.
4. При необходимости я покупаю водительскую лицензию через `/driverlicence` или лицензию на оружие через `/weaponlicence`.
5. Я открываю `/faction`, чтобы выбрать фракцию.
6. Я открываю `/quests`, принимаю доступный квест и следую указателю.
7. Чтобы купить или арендовать квартиру или парковку, я подхожу к её двери и нажимаю ПКМ. Свои объекты я смотрю в `/property`.
8. Я использую `/salary`, чтобы посмотреть размер зарплаты и время до следующего начисления.

## Паспорт и МФЦ

Командой `/mfc` я открываю меню МФЦ. Если паспорта ещё нет, я нажимаю «Получить паспорт» и последовательно указываю:

- имя — от 2 до 24 русских или латинских букв; разрешён дефис;
- фамилию — по тем же правилам;
- возраст — целое число от 14 до 100;
- мужской или женский пол.

После оформления я вижу данные паспорта в меню МФЦ. Паспорт необходим для получения банковской карты и покупки лицензий.

Если база была перенесена со старой версии и возраст равен нулю, я предусмотрел в МФЦ отдельную кнопку для его заполнения.

## Банковская карта, счёт и наличные

Командой `/bankcard` я открываю меню выдачи карты. Для получения карты сначала нужен паспорт. При перевыпуске я удаляю старые карты этого игрока и выдаю одну новую.

Чтобы открыть банк, я беру свою карту в любую руку и нажимаю ПКМ по блоку, который администратор назначил банковским терминалом.

В банковском меню я могу:

- посмотреть баланс счёта;
- посмотреть сумму физических наличных в инвентаре;
- снять деньги стандартными номиналами или указать другую сумму;
- внести выбранную сумму;
- внести все наличные;
- перевести деньги другому игроку, если получатель находится онлайн.

Я сделал наличные отдельными предметами. По умолчанию используются купюры 5000, 2000, 1000, 500, 200, 100, 50, 10, 5, 2 и 1 ₽. При снятии произвольной суммы мод автоматически раскладывает её по доступным номиналам.

## Лицензии

Я разделил лицензии на два независимых меню:

- `/driverlicence` — водительская лицензия;
- `/weaponlicence` — лицензия на оружие.

Для покупки я сначала оформляю паспорт и пополняю банковский счёт. По умолчанию водительская лицензия стоит 2500 ₽, а лицензия на оружие — 10 000 ₽. Я могу изменить цены в конфигурации.

## Зарплата и налог

Командой `/salary` я открываю экран, где показываются начисление, налог и оставшееся время.

По умолчанию я настроил автоматическую выплату каждые 1800 секунд, то есть каждые 30 минут. Деньги поступают на банковский счёт только игрокам, которые находятся онлайн. Стандартный налог — 13%.

Размер зарплаты по умолчанию:

| Уровень фракции | Начисление до налога |
| --- | ---: |
| Без фракции | 1000 ₽ |
| 1 | 1500 ₽ |
| 2 | 2200 ₽ |
| 3 | 3200 ₽ |
| 4 | 4500 ₽ |
| 5 | 6500 ₽ |

Для обхода налога я предусмотрел право `mosvegas.tax.bypass`. Без отдельной настройки налог также не применяется к операторам второго уровня и выше.

## Фракции

Командой `/faction` я открываю список фракций. В стандартной конфигурации я добавил полицию, военных и депутатов.

При вступлении я устанавливаю фракционный уровень и уровень иерархии на 1, очищаю прежний фракционный прогресс и выдаю уникальные предметы выбранной фракции. Чужие фракционные предметы нельзя использовать или хранить: мод автоматически удаляет их из инвентаря.

Чтобы перейти в другую фракцию, я сначала выхожу из текущей. При выходе сбрасываются:

- фракционный уровень и XP;
- уровень иерархии;
- активные фракционные квесты;
- история выполненных фракционных квестов;
- фракционные предметы.

История выполненных стартовых городских квестов при выходе сохраняется.

## Квесты

Командой `/quests` я открываю меню квестов. До вступления во фракцию я вижу стартовые городские задания, а после вступления — задания своей фракции. По умолчанию одновременно можно выполнять не более трёх квестов.

Я реализовал пять типов заданий:

- `TRAVEL` — добраться до одной из точек;
- `ROUTE` — пройти несколько точек по порядку;
- `STAY` — оставаться в зоне указанное время;
- `FIND_ITEM` — найти выбранный предмет в отмеченной зоне;
- `NPC_ITEM` — передать предмет NPC (`GIVE`) или забрать его у NPC (`TAKE`).

Для заданий с координатами я сделал стрелку направления, расстояние в action bar и визуальные маркеры цели. Для NPC-квеста имя сущности должно совпадать со значением `npcName` в конфигурации. Я взаимодействую с такой сущностью ПКМ.

Подробная пошаговая настройка всех типов, последовательных маршрутов, запуска по `/quests start <id>` и выдачи заданий через NPC по полю `giverNpcName` приведена в отдельном файле `QUESTS_CONFIG_GUIDE.md`.

Награда за завершение автоматически поступает на банковский счёт. Фракционные задания также начисляют фракционный XP. Выполненный квест нельзя принять повторно, пока его запись считается завершённой. От активного задания можно отказаться через кнопку с барьером в меню `/quests`, но текущий прогресс будет потерян.

## Недвижимость и парковки

Квартира (`APARTMENT`) и парковка (`PARKING`) — это объекты недвижимости. У каждого объекта есть граница. Всё, что находится внутри границы — блоки, двери, сундуки, мобы, — принадлежит объекту. Объекты создаёт администратор (см. раздел [«Создание недвижимости»](#создание-недвижимости)), а игроки их покупают и арендуют.

### Как купить или арендовать

1. Я подхожу к двери объекта. Если навестись на неё, дверь подсветится: зелёная — у меня есть доступ, красная — нет.
2. Я нажимаю ПКМ по красной двери. Если объект свободен, откроется окно с ценой и кнопкой «Купить за …». Если владелец сдаёт его в аренду и арендатора нет — кнопка «Арендовать за …». Сама дверь при этом не открывается.
3. Я нажимаю кнопку. Деньги списываются с банковского счёта, а объект появляется в моём `/property`. Дверь становится зелёной.

Если объект уже чей-то и не сдаётся, окно не откроется: в строке над панелью появится «Чужая недвижимость».

Деньги берутся только с банковского счёта, наличные в инвентаре не считаются. Если денег не хватает, мод пишет «Недостаточно денег».

### Мои объекты — `/property`

Командой `/property` я открываю список **только своих** объектов. Рядом с названием указана моя роль: «Владелец», «Арендатор» или «Участник». Чужие и свободные объекты здесь не показываются, телепорта нет.

Нажав на объект, я вижу цену, цену аренды и координаты объекта. Дальше кнопки зависят от роли:

| Роль | Что можно сделать в карточке |
| --- | --- |
| Владелец | «Продать государству за 70%», «Выставить в аренду» / «Снять с аренды» |
| Арендатор | «Прекратить аренду» |
| Участник | только посмотреть |

Если у меня нет ни одного объекта, меню пишет «У вас пока нет недвижимости» и подсказывает, как купить.

При продаже владелец получает 70% исходной цены. Объект с действующим арендатором продать нельзя: сначала аренда должна закончиться. Арендная плата списывается один раз при нажатии «Арендовать» и сразу перечисляется владельцу. При досрочном прекращении аренды деньги не возвращаются. Кнопка «Выставить в аренду» есть, только если у объекта задана цена аренды больше нуля.

### Кто может пользоваться квартирой

Внутри границы объекта пользоваться чем-либо могут только:

- владелец;
- арендатор;
- участники, которых добавил администратор;
- администратор с правом `mosvegas.property.access.bypass` (у операторов уровня 3 и выше оно есть по умолчанию).

Всем остальным внутри чужой квартиры или парковки запрещено:

- открывать двери, люки и калитки;
- открывать сундуки, бочки, печи, воронки и другие контейнеры;
- нажимать кнопки и рычаги, пользоваться верстаком, кроватью, наковальней и другими блоками;
- трогать рамки, стойки для брони, картины и мобов;
- ставить и ломать блоки, выливать воду и лаву;
- ставить транспорт на чужую парковку (если транспортный мод проверяет разрешения через `TransportAccess` ядра).

**Свободная квартира тоже закрыта для всех**, пока её никто не купил. Ходить внутри не запрещено: если игрок оказался в квартире, он может передвигаться, но ничего не может трогать. PvP и стрельбу недвижимость не меняет, они настраиваются зонами.

Ломать блоки внутри объекта с включённым `protectBlocks` (по умолчанию включено) не может даже владелец. Это может только игрок с правом `mosvegas.property.build.bypass` или оператор третьего уровня. Так владелец не разберёт стены квартиры.

## Уровни

Я предусмотрел три отдельных показателя:

- фракционный уровень — от 1 до 5 для участника фракции;
- уровень иерархии — от 1 до 100 для участника фракции;
- серверный уровень — от 0 и выше.

Серверный уровень автоматически увеличивается за время онлайн. По умолчанию новый уровень начисляется каждые 3600 секунд, то есть каждый час.

## Администрирование

Административные команды по умолчанию доступны операторам третьего уровня. Вместо OP я могу выдать конкретные права встроенной системой мода.

### Управление правами

```text
/mosvegas permission grant <игрок> <право>
/mosvegas permission revoke <игрок> <право>
```

Игрок должен находиться онлайн. Я могу выдать точное право, группу через звёздочку или полный доступ:

```text
/mosvegas permission grant Player mosvegas.admin.properties.*
/mosvegas permission grant Player mosvegas.faction.police
/mosvegas permission grant Player *
```

Вложенные права наследуются. Например, `mosvegas.admin.properties.*` покрывает права внутри этой ветки.

### Фракции и уровни

```text
/faction admin
/faction level set <игрок> <число>
/faction level give <игрок> <число>
/faction level take <игрок> <число>
/faction hierarchy set <игрок> <число>
/faction hierarchy give <игрок> <число>
/faction hierarchy take <игрок> <число>
/serverlevel set <игрок> <число>
/serverlevel give <игрок> <число>
/serverlevel take <игрок> <число>
```

Через `/faction admin` я могу создать фракцию. ID автоматически переводится в нижний регистр, а неподходящие символы заменяются подчёркиванием. Ранги и уникальные предметы я редактирую в `config/mosvegas-core.json`.

### Квесты

Командой `/quests admin` я открываю админ-меню. В нём я могу включать и выключать существующие квесты и создать новый `TRAVEL`-квест в своей текущей точке. Тип, точки, варианты предметов, награду и остальные параметры я затем уточняю в конфигурации.

### Создание недвижимости

Граница объекта состоит из одной или нескольких **частей**. Каждая часть — прямоугольный объём (параллелепипед), который я выделяю палкой по двум противоположным углам. Всё, что попадает хотя бы в одну часть, принадлежит объекту. Прямоугольная квартира — это одна часть, квартира буквой Г — две, буквой П — три.

#### Палка выделения

1. Я ввожу `/property wand` и получаю палку (огненный стержень «Палка выделения недвижимости»).
2. Держа палку в любой руке, я нажимаю **ЛКМ** по блоку — это первый угол. **ПКМ** по другому блоку — второй угол, по диагонали от первого.
3. Выделение появляется жёлтым контуром. Углы выделения входят в него: блоки, по которым я нажал, тоже будут внутри.

Выделение — это объём, поэтому высота тоже важна. Обычно я ставлю первый угол на **пол в одном углу** комнаты, а второй — на **потолок в противоположном углу**. Удобно выделять вместе со стенами, полом и потолком: тогда их тоже защищает квартира. Координаты блока под прицелом видны на экране F3 (строка «Targeted Block»).

Новое ЛКМ начинает выделение заново. После создания объекта или добавления части выделение сбрасывается, чтобы случайно не добавить одну часть дважды.

#### Прямоугольная квартира или парковка

1. Палкой я выделяю квартиру от пола в одном углу до потолка в противоположном.
2. Я ввожу `/property admin` и нажимаю «Создать квартиру из выделения» или «Создать парковку из выделения».
3. Я ввожу по очереди ID (латиница, цифры, `_` и `-`, например `apt_12`), название, цену покупки и цену аренды. Значение подтверждаю нажатием на правый слот окна наковальни. Цена аренды `0` означает, что объект нельзя сдавать.
4. Откроется админ-меню нового объекта. Если держать палку в руке, граница объекта видна голубым контуром.

#### Квартира сложной формы (Г, П, несколько этажей)

Сложную квартиру я собираю из прямоугольных частей. Порядок всегда одинаковый: **первую часть превращаю в объект, остальные добавляю к нему**.

Пример — квартира буквой П (вид сверху):

```text
 ┌───────┐         ┌───────┐
 │       │         │       │
 │   1   │   двор  │   2   │
 │       │ (не наш)│       │
 │       ├─────────┤       │
 │       │    3    │       │
 └───────┴─────────┴───────┘
```

1. **Часть 1 — левое крыло.** Палкой выделяю левое крыло целиком, от пола до потолка. `/property admin` → «Создать квартиру из выделения» → ввожу ID, название и цены.
2. **Часть 2 — правое крыло.** Выделяю правое крыло. `/property admin` → нажимаю на свою квартиру в списке → «Добавить выделение к границе».
3. **Часть 3 — перемычка между крыльями.** Выделяю её так же и снова «Добавить выделение к границе».
4. Держу палку в руке и проверяю: видны три голубые части, а двор между крыльями не подсвечен. Двор не входит в квартиру, и недвижимость его не защищает: там действуют только общие правила зон города.

Квартира буквой Г — это то же самое, но из двух частей:

```text
 ┌───────┐
 │   1   │
 │       ├─────────┐
 │       │    2    │
 └───────┴─────────┘
```

Двухэтажная квартира — одна часть на каждый этаж (вместе с лестницей). Части могут перекрываться, это не ошибка. Важно только, чтобы между ними не было щелей.

#### Правила, чтобы квартира работала правильно

- **Дверь должна быть внутри границы.** Только такая дверь закрыта для посторонних и по ПКМ предлагает покупку. Если дверь стоит в стене, стену нужно включить в часть.
- **Не пересекайте границы соседних квартир.** Если блок попадает в две квартиры сразу, пользоваться им сможет только тот, у кого есть доступ к обеим. Общую стену отдайте одной из квартир или не включайте ни в одну.
- **Не делайте щелей между частями.** Блок, который не попал ни в одну часть, квартира не защищает: например, сундук в такой щели откроет кто угодно, если это не запрещено зоной города.
- **Двор, коридор и лестничная клетка** — это не часть квартиры. Их не нужно включать в границу.

#### Исправление границы

В админ-меню объекта (`/property admin` → объект):

- **«Добавить выделение к границе»** — добавить текущее жёлтое выделение как новую часть;
- **«Части границы: N»** — список всех частей с координатами. ЛКМ по части удаляет её. Последнюю оставшуюся часть удалить нельзя.

Чтобы полностью заменить границу, я сначала добавляю новые части, а потом удаляю старые. Если открыть «Части границы», граница этого объекта подсвечивается, пока палка в руке.

У старых объектов, созданных до 0.0.4 вокруг точки по радиусу, в «Частях границы» написано «Граница по радиусу». Как только я добавлю такому объекту первую часть, граница будет считаться только по частям, а радиус перестанет действовать.

#### Владельцы и участники

В админ-меню объекта я могу:

- «Назначить владельца» — ввожу ник игрока онлайн; аренда при этом сбрасывается;
- «Удалить владельца» — объект снова свободен, участники удаляются;
- «Добавить участника» — даю доступ другу или соседу по квартире (игрок должен быть онлайн);
- «Список участников» — ЛКМ по игроку убирает его из участников;
- «Телепорт и показать границу» — телепорт к объекту (только в админ-меню);
- «Удалить объект» — объект удаляется вместе с записью о владельце.

#### Список объектов и страницы

В `/property admin` на одной странице помещается 36 объектов. Если их больше, внизу появляются стрелки: справа — «Следующая страница», слева — «Предыдущая страница». Вверху написано, сколько всего объектов и какая страница открыта. Палка выделения теперь во втором слоте нижнего ряда. Кнопка «Назад» из объекта возвращает на ту страницу, где он находится.

#### Название, ID и цены

В админ-меню объекта (`/property admin` → объект) есть кнопки:

- **«Название: … — изменить»** — новое название;
- **«ID: … — изменить»** — новый ID. Заглавные буквы становятся строчными, всё, кроме `a-z`, `0-9`, `_` и `-`, заменяется на `_`. Занятый ID не принимается. Владелец, арендатор, сдача в аренду и участники переходят на новый ID автоматически;
- **«Цена покупки: … — изменить»** и **«Цена аренды: … — изменить»** — целое число от 0. Цена аренды 0 означает, что объект нельзя сдать.

Новая цена действует для следующих покупок и аренды. Уже купленные квартиры остаются у владельцев. Продажа государству считается от текущей цены (70%). Граница и дверь при редактировании не меняются.

#### Сохранность объектов

Квартиры и парковки хранятся в `config/mosvegas-core.json` (название, ID, цены, границы), а владельцы и участники — в `<папка мира>/mosvegas-core-data.json`. При обновлении мода я просто заменяю JAR: оба файла остаются, все отмеченные объекты сохраняются.

- При каждом сохранении конфига прежняя версия кладётся в `config/mosvegas-core.json.bak`. Конфиг сначала пишется во временный файл, поэтому сбой во время записи не портит его.
- Если после ручной правки JSON `/mosvegas reload` не смог прочитать файл, в памяти остаются прежние объекты, а в логе сервера появляется ошибка. Я исправляю файл и повторяю `/mosvegas reload`.
- Если сервер запускается с нечитаемым конфигом, его копия сохраняется в `config/mosvegas-core.json.broken`. Тогда я останавливаю сервер, исправляю `mosvegas-core.json` (или беру `.broken`/`.bak`) и запускаю снова.

#### Проверка готовой квартиры

1. Я держу палку и смотрю на голубые части: они должны покрывать всю квартиру, включая дверь, и не заходить на соседей.
2. Обычным игроком, а не оператором (у оператора обход), я навожусь на дверь: она красная. ПКМ открывает окно «Купить за …».
3. После покупки дверь становится зелёной, а всё внутри открывается. Квартира появляется в `/property` этого игрока.

#### Права администратора недвижимости

### Банковские терминалы

Я навожусь на нужный блок на расстоянии до шести блоков и использую:

```text
/mosvegas bankterminal add
/mosvegas bankterminal remove
```

При разрушении назначенного терминала запись о нём автоматически удаляется.

### Деньги на счёте

```text
/mosvegas money give <игрок> <сумма>
/mosvegas money take <игрок> <сумма>
/mosvegas money set <игрок> <сумма>
```

Команды меняют банковский счёт игрока: `give` зачисляет сумму, `take` списывает, `set` устанавливает точный баланс. Наличные в инвентаре не затрагиваются. Игрок должен быть онлайн. Если на счёте меньше, чем я списываю, команда отказывает и показывает текущий баланс. Каждое изменение пишется в лог сервера и видно другим операторам. Нужно право `mosvegas.admin.money` или `mosvegas.admin`. Команды работают и из консоли сервера.

### Конфигурация и сохранение

```text
/mosvegas reload
/mosvegas save
```

Командой `reload` я перечитываю `config/mosvegas-core.json`, а командой `save` немедленно сохраняю конфигурацию и данные. После ручного редактирования я сначала выполняю `reload`; иначе последующий `save` может записать поверх файла текущую конфигурацию из памяти.

## Настройка `mosvegas-core.json`

Я храню основные параметры в `config/mosvegas-core.json`. Файл создаётся автоматически при первом запуске.

Ключевые поля:

| Поле | Назначение |
| --- | --- |
| `currency` | Обозначение валюты |
| `startingBankBalance` | Начальный баланс нового игрока |
| `salaryIntervalSeconds` | Интервал зарплаты в секундах |
| `taxPercent` | Процент налога |
| `maxActiveQuests` | Максимум активных квестов |
| `serverLevelIntervalSeconds` | Интервал серверного уровня в секундах |
| `cashDenominations` | Разрешённые номиналы наличных |
| `salaryByFactionLevel` | Зарплата по уровню фракции |
| `licencePrices` | Цены лицензий |
| `factions` | Описание фракций, рангов и предметов |
| `quests` | Описание квестов |
| `properties` | Квартиры, парковки и границы зон |
| `bankTerminals` | Координаты банковских терминалов |

Координатная точка содержит `dimension`, `x`, `y`, `z` и `radius`. Граница недвижимости задаётся списком `areas`: каждая часть — блоки от `minX/minY/minZ` до `maxX/maxY/maxZ` включительно, в измерении `location`. Если список пуст, мод строит область вокруг `location` по значению `radius`. Старые поля `min` и `max` при загрузке автоматически превращаются в первую часть `areas`.

```json
"areas": [
  { "minX": 44, "minY": 199, "minZ": 2,  "maxX": 48, "maxY": 203, "maxZ": 14 },
  { "minX": 54, "minY": 199, "minZ": 2,  "maxX": 58, "maxY": 203, "maxZ": 14 },
  { "minX": 49, "minY": 199, "minZ": 10, "maxX": 53, "maxY": 203, "maxZ": 14 }
]
```

Идентификаторы предметов я указываю в формате `minecraft:paper`, `minecraft:iron_sword` и т. п. Измерения указываются в формате `minecraft:overworld`, `minecraft:the_nether` или `minecraft:the_end`.

## Хранение данных

Конфигурацию я храню отдельно от игровых данных:

- `config/mosvegas-core.json` — настройки;
- `<папка мира>/mosvegas-core-data.json` — игроки, паспорта, лицензии, деньги, квесты, недвижимость и права; предыдущая версия — `mosvegas-core-data.json.bak`;
- `<папка мира>/mosvegas-core.db.migrated` (и `-wal`/`-shm`) — SQLite-база версии 0.0.4 или старше после автоматического переноса в JSON.

Мод автоматически сохраняет данные во время работы и при остановке сервера. Для ручной контрольной точки я использую `/mosvegas save`. Файл сначала пишется во временный, поэтому сбой во время записи его не портит. Если файл всё же повреждён, мод при запуске берёт данные из `.bak`, а повреждённый сохраняет как `mosvegas-core-data.json.broken`. Если не читается и `.bak`, сервер не запускается и ничего не перезаписывает.

## Проверка после установки

После установки я проверяю мод так:

1. Сервер запускается без ошибок и показывает версию Mosvegas Core 0.0.4.
2. Клиент входит на сервер без сообщения о несовпадении модов.
3. `/mfc` открывает меню и позволяет оформить паспорт.
4. `/bankcard` выдаёт карту после оформления паспорта.
5. Карта открывает назначенный банковский терминал.
6. `/quests` показывает стартовый квест игроку без фракции.
