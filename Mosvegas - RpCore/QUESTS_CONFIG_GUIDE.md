# Настройка и создание квестов

Эта инструкция описывает все поддерживаемые варианты квестов Mosvegas Core, запуск конкретного квеста командой и выдачу квеста через NPC.

## Где находится конфигурация

Основной файл на сервере:

```text
config/mosvegas-core.json
```

В тестовой среде проекта это `run/config/mosvegas-core.json`.

Перед ручным редактированием рекомендуется сделать резервную копию файла. После сохранения JSON выполните:

```text
/mosvegas reload
```

Если в JSON есть лишняя запятая, пропущенная кавычка или скобка, новый конфиг не загрузится. Не выполняйте `/mosvegas save` до `reload`: иначе текущая конфигурация из памяти может перезаписать ручные изменения.

## Как устроен квест

Все задания находятся в массиве `quests`. Минимальный квест на достижение точки:

```json
{
  "id": "city_hall",
  "name": "Посещение мэрии",
  "description": "Доберитесь до входа в мэрию",
  "type": "TRAVEL",
  "faction": "public",
  "enabled": true,
  "reward": 500,
  "factionXp": 0,
  "staySeconds": 30,
  "giverNpcName": "Секретарь мэрии",
  "npcName": "Квестовый NPC",
  "npcMode": "GIVE",
  "points": [
    {
      "dimension": "minecraft:overworld",
      "x": 120.0,
      "y": 64.0,
      "z": -35.0,
      "radius": 4.0
    }
  ],
  "randomItems": []
}
```

Назначение полей:

| Поле | Что указывать |
| --- | --- |
| `id` | Уникальный технический ID. Используется в команде `/quests start <id>` и в сохранении прогресса. Лучше применять латиницу, цифры, `_` и `-` без пробелов. После запуска сервера ID существующего квеста менять не следует. |
| `name` | Отображаемое название задания для игрока. |
| `description` | Краткое описание цели. Показывается при принятии и в меню NPC. |
| `type` | Один из типов: `TRAVEL`, `ROUTE`, `STAY`, `FIND_ITEM`, `NPC_ITEM`. |
| `faction` | ID фракции, которой доступен квест. Значения `null`, пустая строка, `"public"` и `"starter"` означают стартовый публичный квест для игрока без фракции. |
| `enabled` | `true` — квест доступен; `false` — отключён. |
| `reward` | Денежная награда на банковский счёт. |
| `factionXp` | Фракционный XP за завершение. Для публичного квеста обычно `0`. |
| `staySeconds` | Необходимое время в зоне для типа `STAY`. Другие типы поле игнорируют. |
| `giverNpcName` | Точное видимое имя NPC, который предлагает этот квест по ПКМ. Пустая строка отключает выдачу этого квеста через NPC. |
| `npcName` | Точное видимое имя NPC, с которым взаимодействуют для выполнения `NPC_ITEM`. Это не обязательно тот же NPC, который выдаёт задание. |
| `npcMode` | Для `NPC_ITEM`: `GIVE` — игрок отдаёт предмет; `TAKE` — игрок получает предмет. |
| `points` | Список точек или зон. Их смысл зависит от `type`. |
| `randomItems` | Список ID предметов для случайного выбора в `FIND_ITEM` и `NPC_ITEM`. |

Каждая точка состоит из:

```json
{
  "dimension": "minecraft:overworld",
  "x": 120.0,
  "y": 64.0,
  "z": -35.0,
  "radius": 4.0
}
```

- `dimension` — `minecraft:overworld`, `minecraft:the_nether` или `minecraft:the_end`;
- `x`, `y`, `z` — координаты центра;
- `radius` — радиус срабатывания в блоках. Проверяется полное расстояние, включая высоту `y`.

## Как игрок начинает определённый квест

У каждого задания уже есть название (`name`) и уникальная команда, построенная по его `id`:

```text
/quests start <id>
```

Например, для `"id": "city_hall"`:

```text
/quests start city_hall
```

Команда не обходит правила квестов: задание должно быть включено, подходить фракции игрока, ещё не быть выполнено или активно, а лимит активных квестов не должен быть превышен. Игроку нужны права `mosvegas.command.quests` и `mosvegas.quests.accept`.

Также игрок может открыть `/quests` и выбрать доступное задание в общем меню.

## Как игрок берёт квест у NPC

1. Создайте любую сущность или NPC средствами сервера.
2. Задайте ему видимое имя, например `Секретарь мэрии`.
3. В нужном квесте укажите точное такое же значение:

```json
"giverNpcName": "Секретарь мэрии"
```

4. Выполните `/mosvegas reload`.
5. Игрок нажимает ПКМ по NPC и получает меню его доступных квестов.

Совпадение имени проверяется без учёта регистра, но текст, пробелы и символы должны совпадать. Одному NPC можно назначить несколько квестов: просто поставьте одинаковый `giverNpcName` у нескольких записей.

NPC не создаётся самим конфигом. Конфиг только связывает уже существующую именованную сущность с заданием. Подойдёт обычный моб с пользовательским именем или NPC из совместимого мода, если сервер видит его как сущность и ПКМ не перехватывается другим модом раньше.

Важно различать:

- `giverNpcName` — NPC предлагает и запускает квест;
- `npcName` — NPC участвует в финальной цели типа `NPC_ITEM`.

Они могут совпадать или быть разными.

## Все типы квестов

### `TRAVEL` — дойти до одной точки

Если в `points` указано несколько точек, при каждом принятии выбирается одна случайная. Чтобы цель всегда была одной и той же, оставьте одну точку.

```json
{
  "id": "visit_hospital",
  "name": "Осмотр в больнице",
  "description": "Доберитесь до регистратуры",
  "type": "TRAVEL",
  "faction": "public",
  "enabled": true,
  "reward": 300,
  "factionXp": 0,
  "giverNpcName": "Городской координатор",
  "points": [
    { "dimension": "minecraft:overworld", "x": 80.0, "y": 65.0, "z": 40.0, "radius": 3.0 }
  ],
  "randomItems": []
}
```

Квест завершается сразу после входа игрока в радиус цели.

### `ROUTE` — пройти точки строго последовательно

Порядок прохождения равен порядку объектов в массиве `points`: сначала первый, затем второй и так далее. Для маршрута точки не выбираются случайно.

```json
{
  "id": "police_patrol_route",
  "name": "Полный патруль района",
  "description": "Последовательно проверьте три поста",
  "type": "ROUTE",
  "faction": "police",
  "enabled": true,
  "reward": 1500,
  "factionXp": 2,
  "giverNpcName": "Начальник полиции",
  "points": [
    { "dimension": "minecraft:overworld", "x": 10.0, "y": 64.0, "z": 10.0, "radius": 4.0 },
    { "dimension": "minecraft:overworld", "x": 45.0, "y": 64.0, "z": 30.0, "radius": 4.0 },
    { "dimension": "minecraft:overworld", "x": 90.0, "y": 64.0, "z": -15.0, "radius": 4.0 }
  ],
  "randomItems": []
}
```

Игрок видит указатель только на текущую точку. При достижении промежуточной точки прогресс сохраняется; последняя завершает задание.

### `STAY` — оставаться в зоне

Используется первая точка из `points`. Игрок должен непрерывно находиться в её радиусе `staySeconds` секунд. При выходе из зоны таймер сбрасывается до нуля.

```json
{
  "id": "guard_checkpoint",
  "name": "Дежурство на посту",
  "description": "Оставайтесь на посту две минуты",
  "type": "STAY",
  "faction": "police",
  "enabled": true,
  "reward": 900,
  "factionXp": 1,
  "staySeconds": 120,
  "giverNpcName": "Начальник полиции",
  "points": [
    { "dimension": "minecraft:overworld", "x": 25.0, "y": 64.0, "z": 18.0, "radius": 6.0 }
  ],
  "randomItems": []
}
```

### `FIND_ITEM` — найти предмет в зоне

При принятии случайно выбираются одна точка из `points` и один предмет из `randomItems`. Игроку показывается выбранный предмет и направление до зоны.

```json
{
  "id": "find_evidence_park",
  "name": "Поиск улики",
  "description": "Обыщите отмеченный участок",
  "type": "FIND_ITEM",
  "faction": "police",
  "enabled": true,
  "reward": 1000,
  "factionXp": 2,
  "giverNpcName": "Следователь",
  "points": [
    { "dimension": "minecraft:overworld", "x": 140.0, "y": 64.0, "z": 70.0, "radius": 3.0 },
    { "dimension": "minecraft:overworld", "x": 165.0, "y": 64.0, "z": 55.0, "radius": 3.0 }
  ],
  "randomItems": [
    "minecraft:paper",
    "minecraft:book"
  ]
}
```

В текущей реализации достижение отмеченной зоны завершает этот тип задания. Мод не проверяет, лежит ли физический предмет в мире и был ли он поднят; `randomItems` определяет отображаемый случайный предмет.

### `NPC_ITEM` + `GIVE` — отдать предмет NPC

При принятии случайно выбирается один предмет из `randomItems`. Игрок должен иметь одну штуку этого предмета и нажать ПКМ по сущности с именем из `npcName`; после кнопки «Передать предмет» предмет удаляется, а квест завершается.

```json
{
  "id": "deliver_supplies",
  "name": "Доставка припасов",
  "description": "Отнесите выбранный предмет снабженцу",
  "type": "NPC_ITEM",
  "faction": "military",
  "enabled": true,
  "reward": 1100,
  "factionXp": 1,
  "giverNpcName": "Комендант",
  "npcName": "Снабженец",
  "npcMode": "GIVE",
  "points": [],
  "randomItems": [
    "minecraft:bread",
    "minecraft:iron_ingot"
  ]
}
```

### `NPC_ITEM` + `TAKE` — получить предмет у NPC

Игрок нажимает ПКМ по сущности с именем из `npcName`, получает случайно выбранный предмет и сразу завершает квест.

```json
{
  "id": "take_documents",
  "name": "Получить документы",
  "description": "Заберите документы у секретаря",
  "type": "NPC_ITEM",
  "faction": "deputy",
  "enabled": true,
  "reward": 700,
  "factionXp": 1,
  "giverNpcName": "Руководитель аппарата",
  "npcName": "Секретарь",
  "npcMode": "TAKE",
  "points": [],
  "randomItems": [
    "minecraft:paper",
    "minecraft:writable_book"
  ]
}
```

## Публичные и фракционные задания

Доступ определяется полем `faction`:

```json
"faction": "police"
```

Такой квест видят и принимают только участники фракции с ID `police`.

```json
"faction": "public"
```

или отсутствие/значение `null` делает квест стартовым. Его может принять игрок без фракции. После вступления во фракцию игрок видит только задания своей фракции, а не публичные стартовые задания.

Завершённые задания являются одноразовыми:

- стартовые сохраняются выполненными постоянно;
- история фракционных квестов очищается при выходе или переходе из фракции;
- отказаться от активного задания можно в `/quests`, но прогресс потеряется.

## Добавление квеста без ручного написания основы

Администратор может встать в нужной точке и открыть:

```text
/quests admin
```

Кнопка создания запросит ID, название и описание, после чего добавит `TRAVEL`-квест с текущими координатами. Затем откройте `config/mosvegas-core.json`, найдите запись по `id`, измените `type`, `points`, NPC, предметы и награду и выполните `/mosvegas reload`.

Права администратора: `mosvegas.admin.quests.manage`, `mosvegas.admin.quests` либо OP уровня 3.

## Важные ограничения и проверка

- В `quests` не должно быть двух одинаковых `id`.
- Для `TRAVEL`, `ROUTE`, `STAY` и `FIND_ITEM` нужен непустой `points`; иначе квест не сможет продвигаться.
- Для `FIND_ITEM` и `NPC_ITEM` нужен хотя бы один корректный ID в `randomItems`.
- Для `NPC_ITEM` имя сущности должно точно соответствовать `npcName`.
- Для выдачи через NPC имя сущности должно соответствовать `giverNpcName`.
- Общий лимит одновременно активных заданий задаётся корневым полем `maxActiveQuests`.
- Маркеры целей требуют одинаковую версию мода на сервере и клиенте.

Быстрая проверка после настройки:

1. Выполните `/mosvegas reload` и проверьте консоль на ошибки JSON.
2. Запустите конкретное задание через `/quests start <id>`.
3. Проверьте название, описание и награду.
4. Для `ROUTE` пройдите точки именно в порядке массива.
5. Для выдачи через NPC нажмите ПКМ по сущности с именем `giverNpcName`.
6. Для `NPC_ITEM` отдельно нажмите ПКМ по сущности с именем `npcName`.
